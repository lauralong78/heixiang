# HackKit 演示视频脚本

建议成片时长：约 4 分 30 秒，桌面视口录制，连续展示真实点击、服务端返回和错误状态。视频只介绍黑客松参与者可按需打开的四个工具：进度看板、投票墙、公开 GitHub 仓库检查、项目文档助手；不要把它剪成必须按固定顺序使用的平台。

## 录制前准备

1. 在本机按 README 启动应用，并先完成一次健康检查。确认正式看板的注册、登录、活动、邀请、队伍、任务和进度更新都能在当前环境走通；若后端、迁移或配置未就绪，改录“未启用”的真实错误态，不使用预录成功画面。
2. 准备两个桌面浏览器 profile：
   - Profile A：主持人账号，使用临时演示 ID；
   - Profile B：队长/成员账号，使用另一临时演示 ID。
   两个 profile 使用不同 Cookie，密码只在表单中输入，不朗读、不展示、不写入脚本或录屏文件。需要展示成员加入时，可在 Profile B 退出后用第三个临时账号加入；不要在一个 profile 中伪装两个已登录身份。
3. 准备一个真实、公开、可访问的 GitHub 仓库地址，录制前保存一次检查结果和证据位置。不要使用私有仓库、Token 或带查询参数的链接；不要为了凑状态修改仓库内容。
4. 准备该项目已经确认的真实资料：项目一句话目标、功能、技术栈、运行方式、已知问题、演示地址（若没有就明确留空）。可从仓库 README 或本地说明中复制，不能现场编造。
5. 关闭通知、密码管理器弹窗和个人信息；录制区域只包含桌面浏览器。邀请链接中的 token、账号 ID 和联系方式只短暂展示或打码，链接只通过私下方式使用。
6. 准备失败处理：网络失败、会话过期、权限不足、邀请无效、重复投票或 GitHub 限流出现时，停留在页面上的错误信息，说明“这次操作未确认”，重试一次即可；不要用剪辑、刷新或静态截图制造“已成功”。

## 两个浏览器 profile 的验证方式

录制前用 Profile A 和 Profile B 分别登录不同临时账号。A 创建活动并生成邀请，B 通过邀请加入；两个窗口都刷新一次，确认显示内容来自服务端而不是同一个 localStorage 身份。B 的角色只能执行页面允许的队长/成员操作，尝试越权时应停留在明确的拒绝状态。投票部分用两个 profile 验证资格和单票约束，不能仅靠切换一个页面下拉框冒充另一个账号。由于当前交付是本机单实例，这个验证不等于公网跨设备协作验收。

## 讲解边界与出错原则

- 进度看板和正式投票墙的成功提示，只有在服务端接受并完成后续刷新时才口播“已完成”；“请求发出”“链接已复制”“页面刷新”都不等于业务写入成功。
- 公开 GitHub 检查只覆盖公开元数据和 README 证据。它不证明代码安全、功能真实或部署可用；unknown 必须保持 unknown。
- 文档助手是事实整理、缺失检查、编辑和 Markdown 下载工具。当前脚本不承诺真实 AI 生成、云端保存或对象存储附件。
- 当前没有公网部署、跨设备共享、线上安全授权或已验证的部署链接。不要出现 API Key、密码、Cookie、邀请 token 全文、私有仓库内容或个人联系方式。
- 任何错误都按“停留错误态 → 读出错误原因 → 说明影响 → 重试或跳过”处理。禁止用预置截图、硬编码数据、剪辑跳过中间状态或把“失败/未确认”改口为成功。

## 录制后复核

播放成片检查：四个入口名称与当前页面一致；所有口播都与实际画面和当前仓库状态一致；密码、token、Cookie、Key 和个人资料不可恢复；看板、投票、GitHub 检查、文档下载各至少留下一个可见结果；所有未验证的部署、跨设备、对象存储和 AI 能力都已明确标为边界。
