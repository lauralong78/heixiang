# 黑箱需求基线

状态：SEALED / 第一、二阶段；第三阶段 HK-210 契约已固化
依据：`D:/黑客松工具箱_Codex交接文档.md`（2026-09-24）与用户在本项目中的明确确认。

## 产品定义

黑箱是黑客松现场独立微工具的目录。访客按需打开任意工具，不强制登录，也不存在必须顺序完成的主流程。

## 第一阶段验收

1. 首页具有工具目录、搜索或分类、移动端导航以及清楚的可用状态。
2. 组队名片工具能填写技能、兴趣、角色和简介，实时预览并导出真实 PNG。
3. GitHub 检查器能读取公开仓库，分别显示已确认、缺失、无法确认，并为结论给出证据。
4. 无 `DEEPSEEK_API_KEY` 时上述基础能力仍可用；仓库内存在仅服务端可用的 DeepSeek 适配契约。
5. `npm run lint` 与 `npm run build` 通过；README 能让陌生人复现本地运行。
6. 密钥不进入客户端、不进入仓库；仓库文本不被当作指令执行。

## GitHub 检查项

- 仓库公开且可访问。
- README 存在，并检查：问题与目标用户、核心功能、运行方式或安装、技术栈、困难或问题、演示或部署链接、后续改进。
- 许可证、最近更新时间和仓库主页只作为补充证据，不把语义推断伪装成事实。
- API 限流、无效链接、私有仓库与 GitHub 故障必须有独立错误状态。

## 第二阶段验收

1. 进度看板能创建本地活动、多支队伍和任务，正确计算倒计时与进度，并提供受校验的 JSON 备份和恢复。
2. 现场破冰能根据自愿填写的昵称、技能和兴趣完成公平配对，减少重复，处理奇数轮空和排除关系，并展示可追溯依据。
3. 项目文档助手只根据用户提供的真实资料生成 README 与一页说明，明确列出缺失项，允许编辑、复制和下载 Markdown。
4. 三个工具均无需账号、Key 或网络，刷新后可从浏览器本地恢复；清除数据前需要确认。
5. 首页只有在工具真实闭环通过总控集成验证后才将其标为可用。

## 非目标

- 第一阶段不实现真实登录、队友邀请、投票、签到或共享数据库。
- 不访问私有 GitHub 仓库，不接受用户 Token。
- 不部署、不推送远端；这些需要用户另行授权。
- 不把路线图卡片或演示数据描述成已完成功能。

## 第三阶段：HK-210 共享契约（已固化，尚未实现 UI）

HK-210 只固化三个后续工具可直接实现的数据、身份、权限、状态和演示边界，不把它们接入首页，也不声明线上多人能力已经存在。

### 共同身份与演示模式

- 当前唯一可实现模式是 `same-browser-demo`：身份、活动和记录保存在当前浏览器本地，演示者可以在同一浏览器显式切换“主持人 / 参与者 / 只读观察者”身份，完成真实状态闭环。
- 这不是认证。`identityId`、角色和 localStorage/导入文件都可被本机使用者修改，不能防冒充、不能提供跨设备同步、不能提供跨浏览器共享，也不能作为线上授权依据。界面必须持续显示“本机演示，不支持真实账号和跨设备共享”。
- 身份只有本地显示名和本地 ID；不采集密码、手机号、邮箱、Token、Cookie 或 API Key。主持人权限来自活动 `ownerIdentityId`，参与者权限来自活动参与记录；不能只相信 URL、按钮状态或导入文件中的角色字段。
- 共享角色为 `host | participant | viewer`。主持人管理活动与工具记录；参与者只能管理自己的资料并提交一次性业务记录；观察者只能读公开内容。每个后续工具仍需在命令入口重新检查活动、身份、角色和目标资源。

### 共同活动、参与者与生命周期

- 活动字段至少包含：`id`、`tool`、`title`、`ownerIdentityId`、`status`、`demoMode`、创建/更新时间。工具值固定为 `team-match | vote-wall | checkin-claim`。
- 活动状态为 `draft -> open -> paused -> open -> closed -> archived`，删除为软删除 `deleted`。`draft` 可开放，`open/paused` 可暂停或关闭，关闭后不得写入新的业务记录；删除保留记录和最小审计信息。主持人可从 `deleted` 恢复为 `draft` 或 `archived`，恢复不是回滚已完成的投票、签到或领取。
- 参与者字段至少包含：活动/身份引用、昵称、技能、兴趣、简介、资料可见性和状态。参与者状态为 `active <-> withdrawn -> deleted`；退出会停止新的提交，已完成记录不被抹掉；删除会清除/匿名化展示资料，不能通过普通 UI 恢复，只有导入删除前备份才能恢复。
- 退出、删除、关闭和恢复都必须是明确的命令，需二次确认（删除/关闭尤其如此），并在本地保留时间和原因等最小审计信息。不得把“刷新页面”当作持久化成功证据。

### 共同提交、恢复与恶意输入边界

- 每个变更命令带 `operationId`、`actorIdentityId`、`issuedAt`。同一活动内重复 `operationId` 且参数相同必须返回原结果/幂等成功；同一 `operationId` 改换参数必须拒绝。无论双击、刷新重放还是导入重复，业务唯一键都必须再次检查。
- 导入使用版本化 envelope：`format=hackkit-local-tools`、`version=1`、`mode=same-browser-demo`、工具值、导出时间、身份/活动/参与者和工具 `data`。每个工具还必须深度校验自己的 `data`，不能因为共享 envelope 通过就直接写入。
- 单文件上限 512 KB；共享 ID 只允许受限字符，时间必须是 canonical ISO 字符串，文本、标签、数组和实体数量有上限；未知版本、错误工具、悬空引用、重复 ID、重复标签、非法枚举、对象/数组混淆和损坏 JSON 必须拒绝。导入数据、作品文本、备注、链接和 CSV 字段均视为不可信文本，不能执行 HTML、Markdown、URL、脚本、shell 或模型指令。
- 备份是本地可搬运数据，不是安全凭证。导出不得包含密码、Token、Cookie、API Key 或原始签到凭证；投票去重所需的本地身份 ID 可以存在，但必须明确提示导出文件的隐私风险。

### HK-211 队友匹配

- 资料可见性固定为：`public`（活动内活跃成员可见昵称、技能、兴趣、简介）、`limited`（仅昵称、技能、兴趣）、`private`（只有本人可见，不能进入公开匹配）。不支持联系方式字段。退出或删除资料后不得出现在新建议中。
- 匹配建议必须可追溯：只使用双方主动填写且当前可见的共同兴趣、互补技能、历史相遇次数和排除关系；必须展示证据和“无可比较字段”状态，不得推断年龄、性格、学校、联系方式或其他隐藏属性。
- 邀请状态为 `pending | accepted | rejected | withdrawn | expired`。发送方创建邀请；接收方只能接受或拒绝；发送方只能撤回 pending；同一对活跃参与者只能有一个 pending 邀请；重复发送返回已存在邀请而不新增记录。活动关闭或明确到期时间到达时，未处理的 pending 变为 expired。接受后形成一次 active match，任一方退出/删除时关系变为 ended，另一方只看到已退出/已移除占位信息。
- 参与者退出会取消自己的 pending 邀请并停止匹配；活动仍 open 时可重新加入，但产生新的参与记录，不复活旧邀请。删除资料会软保留关系/审计 ID，清除展示字段；删除前备份可恢复。

### HK-212 观众投票墙

- 活动只支持 `single-choice`：作品字段为提交者、标题、说明、可选 HTTPS 链接和状态 `published | withdrawn | removed`。活动 open 前可修改设置，关闭后作品、投票和结果冻结。
- 投票资格为活动内 `active` 参与者；主持人默认不具备投票资格，只有在 draft 阶段显式设置 `hostEligible=true` 才可投票，设置 open 后锁定。viewer 不可投票。作品提交者可以投票，但不能给自己的作品投票；主持人可选择在活动规则中关闭该约束，必须在 draft 阶段固定并展示。
- 每个合资格身份每个活动只能有一票，唯一键是 `(activityId, voterIdentityId)`；重复点击/重放返回 `ALREADY_VOTED` 和原投票摘要，不增加票数，也不能静默改票。投票身份退出或删除后，已确认投票仍计入结果但展示匿名化；主持人在 close 前只能带原因 void 一票，不能无痕删除。
- 结果展示有 `hidden | live | final`：hidden 只确认“已记录”，live 展示当前计数，final 在 closed 后展示最终计数。主持人可开关展示和导出；导出的结果必须标明统计时间、是否包含 void 票和“本机演示”属性。

### HK-213 签到与领取

- 活动模式为 `check-in | claim | check-in-and-claim`。名单项至少包含本地参与者/展示名、资格状态和不可逆展示的凭证摘要；原始凭证只在创建/重新发放时短暂展示，不写日志、不进 CSV、不作为主持人身份。
- 签到和领取分别按 `(activityId, rosterEntryId, actionKind)` 去重；每种动作成功一次后重复提交返回已有时间和 `ALREADY_RECORDED`，不追加第二行。已签到不等于已领取，只有 `check-in-and-claim` 才允许两种独立记录。
- 记录状态为 `completed | voided`，异常状态至少覆盖未知凭证、凭证属于其他活动、名单已退出/移除、活动未开放、重复提交和输入损坏。异常记录保存安全错误码、时间、操作者和可选原因，不保存原始凭证文本。活动 closed 前，主持人可在本地演示中带原因 void 并重新记录，不能静默覆盖。
- 参与者退出后不能新签到/领取，已完成记录保留；名单移除/身份删除会匿名化展示名但保留审计与计数。主持人只能导出 UTF-8 CSV，列固定为 `activityId,activityTitle,rosterEntryId,participantLabel,actionKind,status,recordedAt,recordId,voidReason`，不含凭证、Token 或自由 HTML；CSV 单元格需处理公式前缀和逗号/换行。

### 第三阶段共同验收门槛

后续工具在首页标为可用前，必须分别通过：刷新恢复、导入/导出往返、非法/超限导入拒绝、身份切换后的角色边界、重复提交幂等、退出/删除/恢复边界、窄屏真实浏览器闭环，并在页面显著说明“本机演示，不支持真实账号、跨设备共享或线上安全授权”。
