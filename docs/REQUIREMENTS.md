# 黑箱需求基线

状态：SEALED / 第一、二阶段
依据：`D:/黑客松工具箱_Codex交接文档.md`（2026-09-24）与用户在本项目中的明确确认。

## 产品定义

黑箱是黑客松现场独立微工具的目录。访客按需打开任意工具，不强制登录，也不存在必须顺序完成的主流程。

## 第一阶段验收

1. 首页具有工具目录、搜索或分类、移动端导航以及清楚的可用状态。
2. 组队名片工具能填写技能、兴趣、角色和简介，实时预览并导出真实 PNG。
3. GitHub 检查器能读取公开仓库，分别显示已确认、缺失、无法确认，并为结论给出证据。
4. 无 `DEEPSEEK_API_KEY` 时上述基础能力仍可用；仓库内存在仅服务端可用的 DeepSeek 适配契约。
5. `npm run lint` 与 `npm run build` 通过；README 能让陌生人复现本地运行。
6. 密钥不进入客户端、不进入仓库；仓库文本不被当作指令执行。

## GitHub 检查项

- 仓库公开且可访问。
- README 存在，并检查：问题与目标用户、核心功能、运行方式或安装、技术栈、困难或问题、演示或部署链接、后续改进。
- 许可证、最近更新时间和仓库主页只作为补充证据，不把语义推断伪装成事实。
- API 限流、无效链接、私有仓库与 GitHub 故障必须有独立错误状态。

## 第二阶段验收

1. 进度看板能创建本地活动、多支队伍和任务，正确计算倒计时与进度，并提供受校验的 JSON 备份和恢复。
2. 现场破冰能根据自愿填写的昵称、技能和兴趣完成公平配对，减少重复，处理奇数轮空和排除关系，并展示可追溯依据。
3. 项目文档助手只根据用户提供的真实资料生成 README 与一页说明，明确列出缺失项，允许编辑、复制和下载 Markdown。
4. 三个工具均无需账号、Key 或网络，刷新后可从浏览器本地恢复；清除数据前需要确认。
5. 首页只有在工具真实闭环通过总控集成验证后才将其标为可用。

## 非目标

- 第一阶段不实现真实登录、队友邀请、投票、签到或共享数据库。
- 不访问私有 GitHub 仓库，不接受用户 Token。
- 不部署、不推送远端；这些需要用户另行授权。
- 不把路线图卡片或演示数据描述成已完成功能。

## 权限边界

总控可以在本地创建任务对话、工作树、代码、测试和提交，以完成本阶段。公开发布、远程推送、线上部署、购买服务和账号级操作不在本次授权内。
