# 黑箱交互反馈基线

适用范围：所有新增或修缮的黑箱工具页面。它不改变每个微工具的独立视觉风格，也不把工具箱改成统一后台；它只规定用户在点击、等待和失败时必须得到真实、可见的反馈。

## 必须具备

1. **可操作元素**：桌面端按钮、可点击卡片和主要链接有明确 `:hover`、`focus-visible` 与 `:active` 反馈。hover 可以上浮/阴影加深，按下必须有压下或缩放反馈；`prefers-reduced-motion` 下保留状态差异但关闭运动。
2. **请求反馈**：任何异步写入都在发送时显示“正在做什么”，成功/失败只能由实际响应决定。不得使用没有服务端确认的“已保存”。
3. **长等待**：持续等待超过约 0.9 秒时显示过程指示条和阶段文案；可说明“正在发起请求 / 正在等待服务端确认 / 仍在等待响应”，但不得伪造不可观测的百分比或后台工作详情。
4. **恢复路径**：失败消息说清楚当前结果是否确认、是否保留已知数据，以及下一步（重试、刷新或检查网络）。
5. **状态可访问**：动态消息使用 `role="status"` 或恰当的 `aria-live`；不只用颜色表达成功、失败或同步状态。

## 可复用实现

- `src/components/shell/operation-progress.tsx`：正式工具可传入真实的同步状态和现有状态文案，显示统一的等待过程条。
- 工具自己的 CSS Module 负责视觉适配；不要把工具私有颜色/布局写到全局样式。
- 新工具在功能验收时，至少覆盖 hover、键盘 focus、按下、正常响应、超过 0.9 秒的等待、失败与 `prefers-reduced-motion`。

## 真实性边界

过程条是“不确定时长的请求状态”，不是服务端进度百分比。若后端没有暴露可验证的阶段或百分比，界面只能说明浏览器已经发起请求、正在等待或尚未确认，不能声称服务器正在执行某个具体任务。
