# 黑箱正式版视觉方向

状态：已确认的视觉方向；页面原型尚未实现

参考：[HumanBench](https://humanbench.ybuild.ai/)

## 1. 核心定位

黑箱采用“手工杂志式的黑客松工具箱”方向：有纸张、贴纸和卡片的亲和感，同时保留真实工具的清晰状态、权限提示和错误反馈。

它不是传统后台，也不是把功能做成装饰性海报。视觉可以活泼，数据和操作必须可靠。

## 2. 视觉语言

| 维度 | 方向 |
| --- | --- |
| 背景 | 米白/暖纸色，允许轻微点阵或纸张纹理，但不能影响文字对比度 |
| 线条 | 黑色或近黑色粗描边，作为卡片、按钮和标签的共同识别符 |
| 阴影 | 轻微偏移的实色阴影，形成纸片叠放感，避免大面积模糊玻璃阴影 |
| 色彩 | 黄色作为主要行动色；粉、蓝、绿、橙作为工具/队伍/状态的区分色 |
| 字体 | 大标题有性格，正文优先可读；中文不能依赖装饰字体，必要时使用显示字体 + 清晰正文 fallback |
| 构图 | 主内容保持明确阅读路径，允许局部不对称、轻微旋转和漂浮标签 |
| 动效 | 页面进入、卡片 hover、保存成功等使用短促微动效；必须支持 reduced motion |
| 语气 | 直接、轻松、略带黑客松现场感，但错误提示不卖萌、不模糊责任 |

禁止事项：紫色渐变后台、平均分布的白色管理卡片、为了装饰而倾斜正文、把“本机演示”伪装成正式多人能力、用动画替代保存/同步/权限反馈。

## 3. 首页应用

首页采用“工具贴纸墙”而不是流程向导：

- 顶部是黑箱品牌、搜索/分类和当前可见状态。
- 中央用一句大标题表达“现场问题，打开即用”。
- 工具卡片使用不同颜色和轻微角度，但每张卡片固定显示名称、用途、状态和入口。
- 漂浮标签只做氛围和提示，例如“组队中”“截止时间？”“README 缺什么？”，不承载关键操作。
- `可用`、`本机演示`、`路线图` 必须视觉上明确区分，未接通功能不显示为可用。

## 4. 进度看板应用

进度看板借用参考站的纸片和卡片语言，但不能照搬单屏答题首页布局：

```text
品牌/活动名/当前用户/角色
        ↓
活动标题 + 倒计时 + 同步状态
        ↓
队伍纸片卡片网格
  ├─ 队伍标题、成员、总体进度
  ├─ 任务纸片、状态、负责人、截止时间
  └─ 附件、编辑、错误/冲突反馈
        ↓
邀请成员 / 新建队伍 / 新建任务
```

必须始终可见或可快速定位：

- 当前登录用户和活动角色
- 数据正在同步、已同步、同步失败或冲突
- 操作成功、无权限、登录过期、网络失败和附件失败
- 当前页面仍是本机演示还是正式服务端能力

危险操作（删除、关闭活动、移除成员）不能只靠颜色区分，必须有文字、确认步骤和真实失败态。

## 5. 桌面视口和可访问性

- 第一阶段只支持桌面端浏览器；所有验收使用桌面视口。暂不实现或承诺手机端、窄屏响应式布局和移动端手势交互。
- 桌面端可以使用不对称网格和较大留白，但主要操作不依赖 hover 才能发现。
- 桌面视口下任务操作目标至少 44px，浮动装饰不遮挡内容。
- 彩色卡片上的文字必须满足可读对比度；颜色不能是状态的唯一表达方式。
- 键盘焦点、错误关联、表单 label、加载状态和 reduced-motion 都属于验收项。
- 卡片旋转角度、噪点和背景点阵必须在低性能桌面设备上可降级。

## 6. 原型验收

页面原型通过以下条件才进入代码接入：

1. 用户能在 5 秒内看懂黑箱是什么，并能找到进度看板入口。
2. 用户能区分正式可用、本机演示和路线图工具。
3. 进度看板首屏能同时看懂活动状态、倒计时、队伍进度和下一步操作。
4. 即使关闭动画，桌面视口中的任务、保存、同步、权限和失败信息仍然清楚；窄屏不属于本阶段验收。
5. 视觉风格有 HumanBench 的纸片/贴纸/粗描边精神，但不会复制其内容、素材或具体页面。

本文件只冻结视觉方向；正式版数据、权限和同步仍以 `FORMAL_BOARD_BACKEND_DESIGN.md` 为准。
