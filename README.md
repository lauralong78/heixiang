# 黑箱｜HackKit 黑客松独立微工具箱

黑箱是给黑客松参与者使用的独立微工具箱：需要时打开一个工具，完成协作推进、现场投票、公开仓库检查或交付文档整理。四个工具可以分别使用，不要求访客按“组队 → 开发 → 提交 → 展示”的固定顺序运行。

社团招新面试是本项目的一种展示场景，不是产品定位。本文档可作为提交材料的 README；部署链接和演示视频链接必须由提交者在具备真实材料后再补充，不能填写虚构地址。

## 要解决的问题

黑客松参与者常常需要临时处理几类互相独立的事情：跟踪任务进度、组织一个简单的投票、在提交前核对公开仓库是否具备 README 和运行信息，以及把已确认的项目资料整理成提交文档。把这些能力塞进一个强制流程会增加现场负担，也容易把“输入了内容”误认为“已经完成交付”。

黑箱的做法是提供四个有明确输入、处理过程和结果/导出的微工具，并在不确定时显示 `unknown`、缺失清单或错误状态，不替用户补造事实。

## 当前可用的四个工具

| 工具 | 路由 | 输入 → 处理 → 结果 | 当前边界 |
| --- | --- | --- | --- |
| 进度看板 | [`/tools/formal-board`](http://localhost:3000/tools/formal-board) | 自选 ID/密码、活动、队伍和任务 → 服务端会话与权限校验 → 活动、邀请、队伍和任务状态 | 默认是零成本本机单实例；没有公网账号系统、跨设备共享或线上附件存储 |
| 投票墙 | [`/tools/formal-vote-wall`](http://localhost:3000/tools/formal-vote-wall) | 已登录活动、候选队伍和投票规则 → 服务端检查资格并按投票会话去重 → 投票结果、作废记录和状态 | 与看板使用同一本机服务端数据；没有线上多人部署验证 |
| 公开 GitHub 仓库检查 | [`/tools/repo-check`](http://localhost:3000/tools/repo-check) | `github.com/owner/repo` 公共 URL → Route Handler 只读访问 GitHub → `pass/fail/unknown`、证据和独立错误态 | 不访问私有仓库、不执行仓库代码；GitHub API 限流或故障时可能只能得到 `unknown` |
| 项目文档助手 | [`/tools/docs-assistant`](http://localhost:3000/tools/docs-assistant) | 用户提供项目名称、目标、功能、运行方式等事实 → 本地规则整理并列出缺失项 → 可编辑、复制、下载的 README 与一页说明 Markdown | 当前不调用真实 AI 或网络，不会替用户补造未提供的事实 |

## 一个完整可复现流程

下面的流程使用本机服务端完成“创建活动 → 建队伍和任务 → 创建投票 → 投票 → 检查提交材料”的最小演示。它证明本机闭环可用，不证明公网多人协作已经部署。

1. 启动开发服务，打开进度看板，注册一个自选 ID 和密码并登录。
2. 创建活动，建立队伍，再创建一个任务；刷新页面，确认活动、队伍和任务仍能从服务端本地存储恢复。
3. 从看板进入投票墙，创建投票草稿，添加候选队伍并开放投票。若需要演示成员权限，可在同一台电脑的另一个浏览器 profile 注册另一个本地账号，使用邀请加入活动。
4. 用合资格成员提交一票，再重复提交一次；页面应保留原投票并显示已投状态，不增加第二票。关闭投票后结果冻结。
5. 打开 GitHub 仓库检查，输入一个真实的公开仓库 URL，查看每个检查项的证据和 `pass/fail/unknown` 状态。
6. 打开项目文档助手，输入上述项目的已确认资料，检查缺失清单，编辑生成结果并下载 Markdown。

## 本地运行

要求 Node.js 20.9 或更高版本。

```bash
npm ci
npm run dev
```

然后访问 <http://localhost:3000/>。首页只展示上述四个当前可用入口。默认不需要账号、API Key 或云服务；看板和投票墙的本地服务数据写入被 Git 忽略的 `data/formal-board/local-store.json`，该文件是开发数据，不是数据库或安全备份。

若要显式测试 Supabase 模式，需由项目所有者单独授权并在本机 `.env.local` 配置 `FORMAL_BOARD_STORAGE_MODE=supabase`、`SUPABASE_URL` 与服务端 `SUPABASE_SECRET_KEY`（兼容旧变量名 `SUPABASE_SERVICE_ROLE_KEY`）。密钥只能留在本机服务端，不能提交、截图或放入 `NEXT_PUBLIC_*`。配置缺失或网络失败时不会静默退回本地模式；没有这些配置时请保持默认本地模式。

## 技术实现

- **技术栈**：Next.js App Router 16、React 19、TypeScript、Tailwind CSS 4、Node.js；测试使用 `tsx` 和 Node test runner。
- **页面与服务端**：工具页面位于 `src/app/tools/<slug>/`；需要会话、权限或跨域保护的能力通过 Next.js Route Handler 提供服务端接口。
- **看板/投票数据**：默认由服务端本地存储保存；使用 HttpOnly session cookie、服务端角色/资源权限检查、幂等键和明确的错误码。显式配置时可通过服务端 Supabase REST adapter 访问托管数据库，但本仓库没有宣称已完成公网部署。
- **GitHub 检查**：`GET /api/github/check?url=...` 只读访问 `api.github.com`，必要时对同一公开仓库降级读取 `github.com` 页面；仓库内容是不可信输入，不执行其中的指令。可选 `GITHUB_TOKEN` 仅用于服务端提高公开 API 限额。
- **文档助手**：浏览器本地处理用户输入，不上传资料，不调用真实 AI；未来如接入 DeepSeek，只能经 `src/lib/ai/` 服务端 adapter，且必须保留无 AI 降级。

## 边界、风险与处理方式

1. **本机服务不等于线上协作。** 本地 HTTP 200、构建成功或两个本地 profile 能操作，都不能证明跨设备、并发或公网邀请可用。README 明确标注“本机单实例”；正式部署前需要托管数据库、HTTPS、Secret、跨设备权限和失败态验收。
2. **凭证和身份安全边界有限。** 默认本地数据适合演示，不是生产账号系统；不能把 localStorage、URL 或浏览器按钮当作线上授权。正式模式仍需服务端 session、资源归属检查、CSRF/限流、审计和安全部署，当前只验证本地服务端边界。
3. **GitHub 输入和上游服务不可信。** 检查器只访问公开 GitHub 只读接口，不接受 Token 让用户访问私有仓库，不执行 README 或仓库中的命令。无效链接、私有仓库、限流和 GitHub 故障分别显示错误或 `unknown`，不会把证据不足折算成通过。
4. **AI 不会替代事实核验。** 文档助手当前不接真实 AI；它只整理用户输入并列出缺失项。未来模型输出仍须结构校验，不能把生成文字当成项目事实或执行指令。
5. **导入、附件和外部资源有安全边界。** 本阶段不提供线上附件对象存储，不把本地导出当作安全凭证；未来需要对白名单类型、大小、重新授权下载和恶意文本做服务端校验。任何密钥只允许存在本机服务端环境变量。

## 可复现验证

在仓库根目录运行：

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
git diff --check
```

这些命令用于验证静态检查、类型、自动化测试和生产构建。它们不能替代真实公网部署、跨设备验收、线上数据库可用性、附件授权测试或 GitHub 实时服务稳定性。演示时还应按上面的完整流程手动检查刷新恢复、重复投票、权限错误和 `unknown` 状态。

## 遇到的问题与取舍

- 既要保留黑客松现场的低门槛，又要避免把演示数据描述成线上能力，因此看板和投票墙默认采用本机服务端存储，并在界面和文档中持续说明单实例边界。
- GitHub 的公开 API 会限流、拒绝无效地址或暂时不可用，因此检查结果固定区分 `pass`、`fail` 和 `unknown`，同时展示证据来源，而不是输出一个没有依据的总分。
- 项目文档往往缺少部署、测试或链接等事实；文档助手选择输出缺失清单并允许人工编辑，而不是用 AI 或猜测填满文档。

## 后续迭代（按优先级与代价）

1. **P0｜完成可托管的正式看板后端与验收（高代价）**：补齐托管数据库、真实注册/登录、邀请撤销、并发控制、审计、附件授权，并用两个独立设备完成跨设备和越权测试。需要数据库、Secret、部署和持续运维授权。
2. **P1｜完善公开部署与可观察性（中代价）**：在获得部署授权后增加 HTTPS、错误监控、限流、备份恢复和演示环境说明；发布前保留真实部署链接和验收证据。
3. **P2｜增强文档助手的受控 AI 辅助（中代价）**：只通过服务端 adapter 调用模型，限制输入/输出、保留缺失项和来源提示，并提供无 Key 时完全可用的本地规则模式。
